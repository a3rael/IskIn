## 2026-08-31 — Человеческое согласование Test Automation Addendum

- **Вопрос:** можно ли внедрить согласованный Test Automation Addendum для Process Stabilization v0.3, заменив Computer Use как основной регрессионный UI-слой на XCTest/Swift Testing и XCUITest/XCUIAutomation?
- **Варианты:** оставить Computer Use основным регрессионным UI-слоем; внедрить addendum с изолированными test data, XCUITest, XCTest/Swift Testing, deterministic `.xcresult` digest и provenance-контролем; изменить продуктовые критерии G1—G5.
- **Принятое решение:** начать реализацию по согласованному allowlist. Computer Use остаётся исключительным каналом для редкой ручной приёмки, исследовательских вопросов и визуальных свойств, не выражаемых assertions.
- **Уточнения решения:** G1—G5 не меняются; XCUITest создаёт screenshot attachments критических состояний; test launch arguments выбирают отдельное локальное test storage со сбросом; digest `.xcresult` считается по отсортированному manifest внутренних файлов и SHA-256 каждого файла; `BudgetCoreChecks.swift` сохраняется до успешного нового XCTest/XCUITest proof; конкретные accessibility identifiers выбирает и документирует Hermes по правилу `budget.<screen>.<control>`.
- **Последствия:** добавление test target и persistence/test seams изменяет evidence scope P0-02; перед первым изменением scope требуется fingerprint checkpoint и structured invalidation, после чего P0-02 возвращается в `evidence-pending` до нового canonical proof. Исторический run `20260831T111930Z-96022` сохраняется. `accepted` не выставляется автоматически; P0-03 не запускается.
- **Владелец решения:** Рукавишников Илья Владимирович.

- **Принятое решение:** цель эксперимента изменена на: «Цель эксперимента — построить и итеративно оптимизировать agent-native PDLC, реализованный средствами Hermes Agent и Hermes Desktop. Процесс должен автономно доводить утверждённое продуктовое намерение до принятого результата с воспроизводимыми доказательствами, соблюдая обязательный уровень качества и минимизируя человеческое управление, время, инструментальные затраты и повторную работу. При проектировании процесса необходимо использовать возможности, инструменты и инфраструктуру Hermes, а также измерять и учитывать его реальные ограничения».

- **Владелец решения:** Рукавишников Илья Владимирович.
- **Границы:** продуктовый intent Budget MVP, P0, критерии G1—G5, существующие доказательства, lifecycle принятых результатов, autonomy policy и evidence scopes не изменяются; процессные улучшения, новый полигон, commit и push этим решением не выполняются.
- **Источники истины:** цель, исследовательский вопрос и критерии успеха — `process/purpose.md`; порядок и набор измерений — `telemetry/metrics.md`.
- **Дата пересмотра:** при появлении evidence, противоречащего обязательному quality/safety floor, или при отдельном human decision.
