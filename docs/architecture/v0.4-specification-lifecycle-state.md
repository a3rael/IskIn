# Архитектура v0.4: specification и lifecycle state

## Срез

Документ описывает source repository ИскИн v0.4 и portable template после разделения immutable product specification и изменяемого lifecycle state. Каноническая реализация находится в `package/template/.iskin/policy_gate.py`; поведение проверяется публичным CLI на временных настоящих Git-репозиториях через `tools/test_lifecycle_events.py`.

## Два слоя состояния

### Immutable product specification

Approval package состоит из:

- human-readable `product-memory/approval-packages/<package_id>.md` — intent, ценность, MVP boundary, outcome definitions, обязательные gates/evidence, uncertainties, риски и ограничения;
- machine-readable companion `product-memory/approval-packages/<package_id>.json` — `schema_version`, package ID/revision, `immutable_content` с SHA-256, outcome IDs, gate IDs и superseded package.

Registry `product-memory/approval-packages.md` связывает продукт с package revision, но не является immutable content конкретного approval. Approval event фиксирует package ID, immutable package paths и checkpoint SHA.

Изменение intent, boundary, outcome definition или обязательного gate изменяет specification. Gate инвалидирует старый approval; требуется новая package revision, pre-approval checkpoint и human approval.

### Mutable append-only lifecycle state

Текущая outcome state хранится событиями:

```text
product-memory/lifecycle-events/<event_id>.json
```

Событие версии 1 содержит event ID, outcome/package/checkpoint, `from_status`, `to_status`, actor, reason, evidence/proof references, human decision reference, UTC timestamp и Git parent SHA. Старые события не переписываются и не удаляются. Projections (`intent.md`, `outcomes.md`, `uncertainties.md`, `evidence.md`, telemetry) читаемы человеком и не становятся новым approval package при обычном переходе.

## State machine

Канонические статусы и переходы:

```text
proposed → approved
approved → in-progress
in-progress → evidence-pending | blocked
evidence-pending → proved | blocked
proved → accepted | reopened
accepted → reopened
blocked → in-progress | evidence-pending
reopened → in-progress | evidence-pending
```

В установленном проекте approval event устанавливает исходное доказанное состояние `approved`; lifecycle events продолжают историю с `approved → in-progress`. Gate запрещает неизвестные статусы, неверный `from_status` и пропуск перехода.

`proved` разрешён только с существующими evidence refs и valid canonical proof/provenance, согласованными с outcome, package и checkpoint. `accepted` требует human decision reference с event ID, `decision: accepted` и `actor: human`.

## Projection contract

Gate не пытается семантически разбирать Markdown. Для последнего lifecycle event `outcomes.md` и `evidence.md` должны содержать exact markers:

```text
<!-- iskin-lifecycle-event: <event_id> -->
<!-- iskin-outcome-id: <outcome_id> -->
<!-- iskin-status: <status> -->
```

Committed projections сверяются с последним committed event. При staged pending event сверка выполняется с pending event; это позволяет безопасно подготовить следующий статус до его commit. Несогласованность блокирует gate.

## Checkpoint boundaries

- `approval_checkpoint` фиксирует human approval event и его decision reference.
- `checkpoint` фиксирует product implementation scope после действующего approval.
- `lifecycle_checkpoint` фиксирует только новый lifecycle event, projections, telemetry, связанные evidence/proof и human decision reference для acceptance. Произвольный product code в этом scope запрещён.

Gate остаётся read-only: он не выполняет `git add`, `commit`, product tests, telemetry writes, evidence writes или внешние действия.

## Проверенная граница

Simulator проходит публичным subprocess CLI через install-fixture, bootstrap, package preparation, approval, implementation, product checkpoint, evidence/proof, lifecycle events и acceptance. На границах выполняются recovery checks, проверяются exit codes, machine status, allowed/forbidden actions, Git cleanliness и read-only поведение. Отрицательные сценарии включают package drift, old-event mutation/deletion, orphan, projection mismatch, stale proof, unknown outcome, wrong transition и unsupported legacy state.

## Не является частью решения

Capability broker, Git hooks, OS-level enforcement, runtime update, release publication и автоматическая миграция legacy projects в этот slice не входят. Unsupported schema/state возвращает объяснимый process-blocked результат.
