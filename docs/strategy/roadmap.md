# Стратегический roadmap ИскИн

**Статус:** канонический стратегический документ репозитория.
**Дата фиксации рамки:** 2026-09-13.

## К чему идём

Человек без технической подготовки описывает бизнес-идею в Hermes Desktop. ИскИн выясняет потребности, предлагает понятное решение и план, получает согласование, автономно реализует утверждённый объём, проверяет результат и помогает ввести его в использование. Человек получает понятные русские инструкции и соразмерный механизм эксплуатации. После пилотирования и в дальнейшем тот же цикл помогает развивать продукт.

ИскИн выполняет функции продуктовой ИТ-команды для небольших инструментов и крупных систем. Повседневную эксплуатацию выполняет созданный отдельный механизм или служба. ИскИн подключается к сложным проблемам как третья линия. Любой выпуск продуктового исправления или обновления требует подтверждения человека. Автоматические эксплуатационные действия допускаются только в заранее разрешённых границах.

Подробнее: [`vision.md`](vision.md).

## Как читать roadmap

- Каждый релиз улучшает один основной наблюдаемый сценарий пользователя. Технические изменения служат этому сценарию.
- `v0.5` — согласованный ближайший приоритет. Структура вех `1.0` и `2.0` согласована. Номера остальных выпусков условны: это последовательность проверяемых возможностей, а не календарь и не утверждённый release scope.
- Дальний шаг может потребовать нескольких выпусков; соседние шаги могут объединиться. Нумерация версий не является десятичной дробью: после `0.9` возможна `0.10`.
- Поздняя отдельная веха означает развитие способности, а не запрет использовать её раньше. Например, безопасность, документация, качественное интервью и архитектура нужны уже сейчас.
- Размер эксперимента выбирается под способность. Маленький эксперимент не ограничивает универсальность ИскИн.

## Веха `1.0`. Полный рабочий цикл небольшого продукта

ИскИн становится рекомендуемым рабочим инструментом для согласованных сценариев небольшого продукта:

> идея → discovery → понятное предложение → human approval → автономная реализация → актуальное доказательство → человеческая приёмка → запуск → пилот → доработка.

Перед выпуском проверяется весь путь на реальном небольшом продукте, включая использование и изменение по результатам пилота. Дополнительно проверяется основной путь с другим нетехническим человеком без помощи авторов ИскИн. Подтверждаются работа с независимыми проектами и обновление самого ИскИн с продолжением существующей работы.

Количество законченных промежуточных релизов не подменяет эту сквозную проверку. Универсальность для больших продуктов сохраняется как видение; `1.0` не заявляет доказанность всех сложных сценариев и не требует завершить весь будущий механизм эксплуатации.

## Веха `2.0`. Более сложные продукты и полный путь их поддержки

Кандидат на вторую зрелую основу после интегрированной проверки:

> идея → discovery → понятное предложение → human approval → автономная реализация → актуальное доказательство → человеческая приёмка → согласованный ввод в использование → работа отдельного механизма эксплуатации → обратная связь → развитие продукта.

Проверяется реальный продукт с согласованными признаками сложности: связанными частями, поэтапным развитием, интеграциями и подходящим механизмом эксплуатации. Сквозной сценарий включает эксплуатационную проблему, передачу сложного дефекта ИскИн, подготовку исправления и выпуск после подтверждения человека. Включается проверка понятности полного пути для другого нетехнического заказчика.

ИскИн не становится повседневным оператором. Отдельная эксплуатация восстанавливает работу в заранее разрешённых пределах; продуктовые выпуски подтверждает человек. Это не обещание поддержки любой системы любого масштаба. Конкретные признаки сложности, условия зрелости и границы поддержки потребуется согласовать перед экспериментом.

## После `2.0`

Расширение проверенных типов и масштабов продуктов, повышение надёжности, эффективности и удобства, развитие интеграций и поддержки. Детальная последовательность определяется по рабочему использованию `1.x` и `2.0`. Улучшения не прекращаются при достижении мажорной вехи.

## Сквозные требования

С `v0.5` ведётся достаточный минимальный учёт, чтобы проверить её цель. `v0.6` укрепляет измерение, а далее эффект каждого релиза проверяется на сопоставимом сценарии: время, человеческое управление ходом работы, повторы/rework, качество и безопасность. Универсальные численные пороги без baseline не назначаются.

Возможности Hermes анализируются при появлении соответствующей потребности и после изменений платформы. `v0.7` — отдельная веха выбора и первого проверенного применения; последующие шаги используют подтверждённые подходы. Канбан, профиль, бот или субагент не становятся обязательным ритуалом только из-за своего наличия.

Понятный русский язык, простые необходимые действия человека, безопасность, контроль полномочий, актуальность evidence и соразмерность процесса обязательны на всём пути. Масштабирование не должно делать маленькие продукты тяжелее без необходимости.
