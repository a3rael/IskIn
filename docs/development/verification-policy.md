# Политика воспроизводимых проверок разработки ИскИн

**Область:** только разработка репозитория ИскИн.
**Статус:** действует по решению `docs/decisions/2026-09-02-local-commit-policy.md`.

Эта политика не входит в устанавливаемый пакет и не является универсальной commit-политикой проектов, использующих ИскИн. Она не требует и не описывает изменений в `package/template/**`.

## Результаты проверок

Каждая проверка получает один из статусов:

- `PASS` — проверка реально выполнена и прошла;
- `FAIL` — проверка выполнена и обнаружила нарушение;
- `NOT_APPLICABLE` — проверка не относится к составу изменения; обязательно указывается конкретная причина;
- невозможность проверки (`FAIL_ENV`, отсутствие команды, неизвестный тип) блокирует автономный коммит до решения человека или дополнения этой политики.

`NOT_APPLICABLE` нельзя использовать вместо запуска проверки, если её область затронута.

## Каноническая команда инвариантов репозитория

Если отсутствует единая команда для статических инвариантов, используется:

```text
python3 tools/verify_repository.py
```

Инструмент использует только стандартную библиотеку Python, не меняет файлы, не обращается к сети и не проверяет Budget-продуктовые гейты. Он проверяет структуру установленного шаблона, JSON, project skills, локальные ссылки, запрещённые артефакты, симлинки и секретные/приватные файлы по безопасным эвристикам.

## Матрица обязательных проверок

### Любой коммит

До создания коммита Hermes обязан:

1. просмотреть полный список подготовленных файлов:

   ```text
   git diff --cached --name-status
   git diff --cached --stat
   ```

2. подтвердить отсутствие посторонних изменений и соответствие состава одной понятной логической цели;
3. выполнить:

   ```text
   git diff --cached --check
   ```

4. проверить, что в index не попали `.DS_Store`, `._*`, `__pycache__`, `*.pyc`, `*.pyo`, `*.xcresult`, временные архивы, тестовые release-артефакты и другие временные файлы; канонический исходник `installer/install-iskin.py` исключение и разрешён, release-копии вне `installer/` запрещены;
5. проверить отсутствие неожиданных симлинков;
6. проверить отсутствие секретов и приватных данных; значения секретов никогда не выводятся в отчёт;
7. проверить, что незавершённая работа и неизвестные изменения исключены или вынесены на human gate.

После staging список index проверяется повторно. Если хотя бы одна обязательная проверка получила `FAIL` или не может быть выполнена, коммит запрещён.

### Изменена документация

Для любого изменения Markdown-документа обязательны:

- проверка внутренних Markdown-ссылок;
- проверка существования каждого локального пути, на который ссылается документ;
- проверка указателей на канонические источники, если документ заявляет правило.

### Изменены `installer/*.py`

Обязательны:

```text
python3 -m unittest installer/test_verify_release.py -v
python3 -m unittest discover -s installer -p 'test_*.py' -v
python3 -m py_compile installer/install-iskin.py installer/verify_release.py installer/build_release.py installer/test_verify_release.py installer/test_install_iskin.py installer/test_build_release.py
```

Полный discovery-набор обязателен всегда; запуск только одного файла не считается достаточным. Точный список файлов для `py_compile` обновляется вместе с появлением новых Python-файлов установщика.

### Изменены `tools/*.py`

Обязательны:

```text
python3 -m py_compile tools/verify_repository.py
python3 tools/verify_repository.py
```

Если появятся дополнительные исполняемые инструменты в `tools/`, для них сначала добавляется точная команда проверки в эту матрицу.

### Изменён `package/template/**`

Обязательна каноническая команда `python3 tools/verify_repository.py`, которая должна подтвердить:

- утверждённую структуру шаблона;
- отсутствие недостающих и неожиданных файлов;
- корректность JSON;
- отсутствие заполненных продуктовых записей;
- отсутствие Budget- и toolchain-specific содержимого;
- уникальность имён навыков;
- наличие completion criteria в навыках;
- корректность внутренних ссылок;
- отсутствие симлинков.

Эта проверка относится к составу устанавливаемого шаблона и не переносит commit-политику в пакет.

### Изменены несколько областей

Выполняется объединение всех проверок для затронутых областей. Нельзя заменить полный набор проверок более узкой проверкой последней изменённой области.

### Изменены `experiments/**`

Изменения в `experiments/**` должны быть явно разрешены текущей задачей. Применяются проверки, определённые конкретным экспериментом. Если такие проверки не определены, Hermes останавливается до согласования и не назначает себе произвольный набор.

Исторический снимок Budget не превращается этой политикой в активный набор инструкций ИскИн.

### Появился новый тип файла

Если матрица не определяет проверку нового исполняемого или значимого типа файла, Hermes сначала предлагает дополнение к этой policy. До определения проверки файл не считается готовым к автономному коммиту.

## Секреты и приватные данные

Статический инструмент выполняет безопасную эвристическую проверку имён credential-файлов и распространённых маркеров секретов, не печатая значения. Это не заменяет юридическую или полноценную privacy review. Любое подозрение блокирует коммит до ручной проверки.

## Что не следует из коммита

Локальный коммит не означает:

- human acceptance;
- стабильный release;
- наличие remote;
- push или публикацию;
- создание тега;
- готовность устанавливаемого пакета к production-установке.
