# Наблюдение v0.4: смешение specification и lifecycle metadata

## Факты recovery и границы

- Recovery новой сессией сохранил существующее mutation evidence.
- Реальный mutating smoke не повторялся.
- Provenance был исправлен.
- Были созданы checkpoint-коммиты.
- Gate правильно обнаружил изменение package path.
- Архитектурная модель ошибочно смешивала immutable specification и lifecycle metadata.
- Предложение новой approval revision только ради изменения статуса признано неправильным.
- Текущий запуск остановлен до Telegram gates.
- Bootstrap и package-preparation потребовали две лишние human escalation.
- Обязательное product approval и выбор внешнего test target не считаются нежелательным steering.

## Интерпретация

Эти факты относятся к наблюдению конкретного эксперимента, а не являются универсальным product rule. Исправление обобщено в отдельное решение v0.4: immutable approval specification хранится в package Markdown и companion/index, а изменяемый lifecycle — в append-only machine events и projections.

Новая модель сохраняет прежние human boundaries: approval полного package и выбор внешнего test target остаются отдельными человеческими решениями. Она меняет только то, что обычный lifecycle transition не пересобирает и не инвалидирует утверждённую specification.
