# Наблюдение v0.4: history boundary executable policy gate

## Факты эксперимента

В живом sandbox автономно были созданы:

- bootstrap checkpoint `0174c78` — `chore: bootstrap iskin project baseline`;
- pre-approval checkpoint `bffbb71` — `iskin: pre-approval checkpoint: AP-20260907T202853Z-telegram-reminders-mvp`.

До product implementation gate вернул machine blocker:

```text
PROCESS_BLOCKED
PRODUCT_OR_EVIDENCE_BEFORE_CHECKPOINT
```

Hermes корректно остановился: product implementation не начиналась, human approval не запрашивался.

## Классификационный дефект

Gate включал в проверку product/evidence всю историю от корневого commit до pre-approval checkpoint. Поэтому verified baseline fixture:

```text
process/fixtures/provenance-drift/template/proof-record.json
```

была ошибочно классифицирована как product evidence, хотя она входила в bootstrap manifest, имела соответствующий hash в bootstrap commit и не изменялась между checkpoint-ами.

Дефект находился в history classification policy gate, а не в продуктовой реализации. Содержательного human steering продукта не произошло; возникла обязательная process/tooling escalation.

## Требуемая граница и исправление

Verified bootstrap commit стал нижней временной границей product lifecycle. Gate теперь принимает только единственный root commit с exact marker:

```text
chore: bootstrap iskin project baseline
```

Дополнительно проверяются exact bootstrap scope, добавленные пути и baseline hashes из verified manifest. Проверка product code/evidence до pre-approval checkpoint анализирует только commits после verified bootstrap commit и до checkpoint. Immutable baseline drift блокируется отдельно, включая случай изменения и последующего восстановления файла. Исключение по имени `proof-record.json` или по каталогу fixture не добавлялось.

## Граница наблюдения

- автономное создание bootstrap и pre-approval checkpoint подтверждено;
- machine blocker был корректно соблюдён;
- product implementation не запускалась;
- human approval не запрашивался;
- содержательного steering продукта не было;
- tooling/process escalation была обязательной;
- наблюдение сохранено в source repository, не в product sandbox.
