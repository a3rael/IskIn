# Решение v0.4: immutable specification и append-only lifecycle state

## Контекст

Живой эксперимент показал, что approval package включал `intent.md`, `outcomes.md` и `uncertainties.md`. Обычный переход outcome к evidence-pending или proved изменял lifecycle metadata в этих файлах, после чего gate ошибочно классифицировал изменение как drift утверждённого package и требовал новую human approval revision.

Это смешивало два разных факта:

```text
утверждённое содержание продукта → immutable
текущий lifecycle, evidence и результаты → mutable/append-only
```

## Решение

1. Approval package хранится отдельной human-readable specification и machine-readable companion/index.
2. Companion/index версии 1 содержит package ID/revision, SHA-256 immutable content, outcome IDs, gate IDs и superseded package.
3. В approval event schema v2 `package_paths` содержат только immutable specification/index. Projections и telemetry из них исключены.
4. Lifecycle state хранится versioned JSON events в `product-memory/lifecycle-events/`.
5. Допустимые lifecycle transitions задаются одной явной state machine и проверяются executable gate.
6. Projection files остаются human-readable views. Их связь с event log проверяется exact markers, без семантического Markdown parsing.
7. Для обычного перехода используется отдельный read-only action `lifecycle_checkpoint`; новая package revision требуется только при изменении specification.
8. `proved` требует актуальных canonical evidence/provenance; `accepted` требует отдельного human decision.
9. Старые events append-only: mutation, deletion, orphan, stale proof и projection mismatch fail closed.
10. Не реализуются capability broker, Git hooks, OS-level enforcement и automatic legacy migration.

## Последствия

Переходы `approved → in-progress → evidence-pending → proved → accepted` больше не требуют новой approval revision сами по себе. Specification drift по-прежнему инвалидирует approval. Установленные проекты со старыми machine schemas не интерпретируются молча: gate возвращает unsupported/process-blocked status.

## Доказательства

Поведение проверяется `tools/test_lifecycle_events.py` на временном Git repository с полным актуальным template и публичным CLI `.iskin/policy_gate.py`. Проверяются полный lifecycle, recovery на границах, read-only gate, package drift, event append-only, projection/evidence/provenance и обязательные отрицательные сценарии.
