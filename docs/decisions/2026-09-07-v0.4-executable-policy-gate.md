# Решение v0.4: read-only executable lifecycle policy gate

**Дата:** 2026-09-07
**Статус:** process contract v0.4; локальный operational guard
**Связано с:** `docs/decisions/2026-09-07-v0.4-pre-approval-checkpoint.md` и `docs/decisions/2026-09-07-v0.4-second-recovery-observation.md`

## Решение

Критические lifecycle-переходы ИскИн проверяются не только global skills и Markdown-контрактами, но и канонической локальной read-only программой, устанавливаемой в проект:

```text
python3 .iskin/policy_gate.py --action <action>
```

Gate использует только Python standard library и локальный Git. Он не создаёт и не изменяет файлы, index, `HEAD`, telemetry или внешнее состояние; не запускает product checks и не выполняет stage, commit, reset, checkout, delete, push, tag, release или интеграционные вызовы.

## Machine-readable contract

Канонический versioned state находится в `.iskin/policy_state.json` и имеет `schema_version: 1`. В нём структурно задаются:

- `lifecycle`: `discovery`, `awaiting_approval` или `implementation_allowed`;
- `approval_state`: `none`, `prepared` или `approved`;
- `package.package_id` и точный `package_paths`;
- `approval_event` с package ID, checkpoint SHA, вопросом, фактическим ответом, actor, `package_displayed_in_previous_agent_turn: true` и `implementation_authorized: true`;
- machine-readable patterns product code и product evidence.

Повреждённые, неизвестные или противоречивые state/schema дают fail closed. Human-readable package и decisions могут оставаться Markdown, но lifecycle-решение не извлекается из произвольных фраз Markdown.

## Output и exit codes

Каждый запуск печатает один детерминированный JSON-объект с полями:

```text
schema_version
status
reason_codes
allowed_actions
forbidden_actions
package_id
checkpoint_sha
approval_state
lifecycle
human_evidence_boundary
```

`status` принимает только:

- `DISCOVERY_ALLOWED` — package отсутствует, разрешены discovery и подготовка package;
- `AWAITING_APPROVAL` — package подготовлен или checkpoint существует, но implementation не разрешена;
- `IMPLEMENTATION_ALLOWED` — approval event точно ссылается на checkpoint, package не drift-нул и до approval нет product code/evidence;
- `PROCESS_BLOCKED` — обязательное состояние отсутствует, повреждено, противоречиво или нарушен порядок lifecycle.

Для конкретного critical action exit `0` означает разрешение. Запрошенные `change_product`, `prove_result` и `checkpoint` запрещены при любом другом exit. `read_only_recovery` может вернуть диагностируемый `PROCESS_BLOCKED` с exit `0`, но fail-closed ошибки, при которых gate не может проверить состояние, всегда имеют ненулевой exit.

## Проверяемые Git-факты

Gate проверяет:

- наличие package и registry reference;
- отдельный commit с marker `iskin: pre-approval checkpoint: <package_id>`;
- ancestry checkpoint относительно `HEAD`;
- отсутствие product code/evidence в checkpoint и во всех commits до approval;
- наличие durable machine approval event в commit после checkpoint;
- точные package ID и checkpoint SHA;
- отсутствие изменений package paths после checkpoint;
- согласованность lifecycle, approval state и Git state.

Gate не является OS-level sandbox, capability broker или Git hook. Он не может криптографически доказать, что человек действительно видел conversational message. Поле `package_displayed_in_previous_agent_turn: true` остаётся human/conversational evidence boundary и не подменяет фактическую проверку человеком.

## Integration points

- новая сессия/recovery: `--action read_only_recovery`;
- перед `change-product`: `--action change_product`;
- перед canonical `prove-result`: `--action prove_result`;
- перед lifecycle/checkpoint commit: `--action checkpoint`;
- после human approval и до реализации: повторный `--action change_product`.

При `PROCESS_BLOCKED` orchestration немедленно прекращает implementation, proof, product checks и telemetry writes, не создаёт retroactive package/checkpoint и возвращает человеку read-only отчёт.

## Проверка

`tools/test_policy_gate.py` выполняет поведенческие проверки на временных настоящих Git-репозиториях: discovery, dirty package, awaiting approval, valid approval, pre-checkpoint product code/evidence, invalid checkpoint, drift, corrupted state, missing Git, allowed post-approval product change, blocked critical actions и отсутствие side effects gate.
