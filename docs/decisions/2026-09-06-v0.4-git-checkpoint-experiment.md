# Решение v0.4: Git checkpoint experiment

**Дата:** 2026-09-06
**Статус:** утверждено человеком
**Тип:** отдельное human decision об архитектуре первого эксперимента v0.4
**Область:** только будущий Git-based product sandbox первого эксперимента v0.4; не устанавливаемый пакет, не runtime Hermes и не стабильный baseline v0.3

## Решение

Первый эксперимент ИскИн v0.4 использует Git как обязательный durable-контур восстановления. Каждый product sandbox эксперимента является отдельным Git-репозиторием.

Проверенный локальный commit является durable checkpoint законченного перехода процесса. Он не является human acceptance, release, публикацией или разрешением любого внешнего Git-действия.

Это решение уточняет устав v0.4 (`2026-09-06-v0.4-experiment-charter.md`), но не реализует навыки, installer, runtime-механизмы или универсальную Git-политику установленного ядра.

## Состав checkpoint

Checkpoint-коммит создаётся после законченного и проверенного перехода процесса и включает согласованное состояние:

- продуктовых файлов, относящихся к переходу;
- активного outcome и его lifecycle-статуса;
- фактических evidence, provenance и proof records;
- telemetry завершённого шага;
- следующего допустимого действия;
- действующих границ полномочий.

Коммит не создаётся после каждого tool-вызова. Количество коммитов не является метрикой успеха.

## Разрешённые автономные локальные commits

В product sandbox первого эксперимента Hermes может самостоятельно создать локальный checkpoint-коммит только при одновременном выполнении всех условий:

1. завершён один связный переход процесса;
2. прошли все применимые обязательные проверки;
3. product memory, evidence и telemetry согласованы с фактическим состоянием;
4. записанные данные перечитаны;
5. отсутствуют неразрешённые ошибки и неизвестный результат внешнего действия;
6. staged scope содержит только файлы, относящиеся к этому переходу;
7. `git diff --cached --check` проходит;
8. commit не включает посторонние пользовательские изменения.

При невыполнении любого условия Hermes не создаёт checkpoint-коммит. Он сохраняет наблюдаемые факты без удаления или скрытия изменений и продолжает только в пределах подтверждённых полномочий либо эскалирует вопрос человеку.

Remote, push, tag, merge, GitHub Release и публикация не разрешаются этим решением. Для каждого из них нужно отдельное human decision.

## Recovery contract

Transcript Hermes является вспомогательным источником контекста, но не каноническим состоянием процесса.

Новая сессия восстанавливает состояние последовательно из:

1. Git branch, HEAD, status и diff;
2. `product-memory`;
3. evidence и proof records;
4. telemetry;
5. process policy;
6. версии или revision использованных навыков.

Если рабочее дерево чистое, `HEAD` считается последним устойчивым checkpoint.

Если рабочее дерево грязное, новая сессия считает возможным прерывание между checkpoint. Она не удаляет, не откатывает и не коммитит изменения автоматически. До продолжения она определяет фактически завершённые действия, проверяет побочные эффекты и evidence и затем:

- продолжает с безопасного подтверждённого шага;
- повторяет только безопасную необходимую проверку; либо
- эскалирует подтверждённый blocker или неопределённость вне полномочий.

## Глобальные навыки

Первый эксперимент проводится в основном профиле Hermes. Планируется глобальная установка навыков ИскИн v0.4; product sandbox не содержит их локальных копий.

До первой глобальной установки или обновления требуется отдельное human decision, в рамках которого должны быть подготовлены:

- read-only снимок текущего состава навыков;
- устанавливаемая версия и provenance;
- восстановимый способ вернуться к прежнему состоянию.

Ни установка, ни обновление, ни удаление global skills этим решением не разрешаются.

## Совместимость навыков и evidence

Для воспроизводимости evidence и telemetry фиксируют версию или revision использованных навыков. Изменение байтов навыка само по себе не делает evidence неактуальным.

Работа блокируется только при подтверждённой несовместимости обязательного интерфейса между global ИскИн и проектом, включая:

- schema project state;
- lifecycle;
- process contract;
- evidence/provenance contract;
- иной явно обязательный интерфейс.

Обычное улучшение формулировок навыка без такой несовместимости не invalidates существующее evidence.

## Критерий завершённости решения

Решение зафиксировано, когда roadmap и индексы ссылаются на него, а отдельная спецификация определяет два последовательных проверяемых сценария: восстановление после checkpoint и recovery грязного дерева между checkpoint.
