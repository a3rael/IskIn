# Безопасная установка ИскИн v0.3

**Дата:** 2026-09-02
**Статус:** утверждено человеком
**Тип:** отдельное human decision о границе надёжности локальной установки
**Область:** локальный установщик release-пакета ИскИн v0.3; не является частью устанавливаемого шаблона

## Решение

Установщик v0.3 гарантирует:

- полную проверку release-пакета до записи в целевой проект;
- отсутствие перезаписи существующих файлов;
- сохранение существующего `.git` без изменений;
- удаление всех файлов и каталогов, созданных установщиком, при обычной обнаруженной ошибке;
- создание `.iskin/installation-manifest.json` последним среди установочных metadata-файлов как признак успешно завершённой установки.

Для несуществующей целевой папки установщик готовит содержимое в staging-каталоге на той же файловой системе и публикует готовую папку атомарным переименованием. Для существующей пустой или `.git`-only папки он переносит только новые файлы и отслеживает созданные пути для rollback.

## Допустимый target

Установка разрешена только в:

- несуществующую папку;
- существующую пустую папку;
- существующую папку, содержащую только обычную директорию `.git` или обычный Git worktree-файл `.git`.

Симлинк вместо target или `.git` запрещён. Установщик не следует через пользовательские симлинки при записи и не изменяет существующий `.git`.

## Явный Git init

Создание Git-метаданных выполняется только с флагом `--init-git`. По умолчанию `git init` не вызывается. Флаг не создаёт commit, remote, branch ref, tag и не выполняет push.

## Обычные ошибки и crash boundary

При обнаруженной ошибке проверки, target-валидации или записи установщик удаляет только созданные им пути и возвращает существующую target-папку к исходному состоянию. Существующие данные не удаляются и не перезаписываются.

Внезапное выключение компьютера, `SIGKILL` и аварийное завершение операционной системы во время записи являются известным ограничением v0.3. Crash-safe recovery и журнал незавершённой установки отложены на будущую версию. После такого события ручная проверка target может потребоваться; наличие manifest не следует считать доказательством восстановления.

## Технический installation manifest v1

После успешной установки создаются:

```text
.iskin/version
.iskin/installation-manifest.json
```

`installation-manifest.json` имеет ровно такие поля:

```json
{
  "schema_version": 1,
  "release_version": "0.3.0",
  "archive_sha256": "64 lowercase hexadecimal characters",
  "files": [
    {
      "path": "relative/installed/file",
      "sha256": "64 lowercase hexadecimal characters"
    }
  ]
}
```

`files` содержит отсортированный полный список всех установленных файлов ИскИн, кроме самого `installation-manifest.json`, включая `.iskin/version`. Пути относительны target, используют `/`, не содержат абсолютных компонентов, `.`, `..`, обратных слешей и симлинков. Неизвестные поля и недетерминированные данные запрещены.

Installation manifest является техническим контрактом установщика v0.3 и не меняет продуктовую методологию ИскИн.

## Граница публикации

Канонический standalone-исходник установщика находится в `installer/install-iskin.py`. Будущий release может публиковать этот файл как `install-iskin.py`; текущая задача не создаёт постоянных release-артефактов и не выполняет публикацию.
