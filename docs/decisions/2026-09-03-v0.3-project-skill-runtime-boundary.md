# Ограничение runtime-доступности проектных навыков ИскИн v0.3

**Дата:** 2026-09-03
**Статус:** утверждено человеком
**Тип:** отдельное human decision о границе совместимости с Hermes Desktop
**Область:** локальные проектные навыки ИскИн и их runtime-загрузка; не является продуктовой неопределённостью установленного проекта

## Вопрос

Как трактовать локальные проектные навыки ИскИн v0.3 при ограничении текущего Hermes Desktop runtime, который передаёт относительный `TERMINAL_CWD`?

## Принятое решение

Для v0.3 утверждено:

- локальные проектные навыки остаются в `.hermes/skills/<skill-name>/SKILL.md`;
- `hermes skills trust` является обязательным ручным шагом подключения навыков после установки;
- установщик не выполняет `hermes skills trust` и только печатает человеку точную следующую команду;
- наличие файла и успешный `hermes skills list` сами по себе не считаются доказательством runtime-доступности;
- runtime-доступность подтверждается только наличием имени навыка в runtime-каталоге текущей сессии и успешной загрузкой навыка по имени;
- после доверия требуется полностью перезапустить Hermes Desktop, открыть папку как Hermes Desktop Project и создать новую сессию;
- шесть навыков v0.3 проверяются отдельно: `understand-state`, `choose-next-action`, `change-product`, `prove-result`, `challenge-result`, `control-pilot`.

## Принятое ограничение

В текущем Hermes Desktop подтверждено, что runtime получает `TERMINAL_CWD=./workspace`, хотя фактический `PWD` является абсолютным путём проекта. Поэтому текущий Hermes Desktop runtime может не разрешить локальные навыки даже после успешного `hermes skills trust`.

Контрольный отдельный runtime-процесс с корректным абсолютным `TERMINAL_CWD` успешно загружает все шесть навыков версии `0.3.0`. Это локализует проблему в текущем Desktop runtime-контуре, но не доказывает доступность навыков в уже открытой пользовательской сессии.

Ограничение принимается для базовой v0.3. Если загрузка по имени завершается `Skill not found`, состояние классифицируется как отсутствие runtime-доступности, а не как успешное подключение. Файловый fallback вместо runtime-навыков не добавляется.

## Граница доказательства

В отчётах и проверках различаются три независимых состояния:

1. `SKILL.md` существует на диске;
2. навык указан runtime как `local/enabled`;
3. навык фактически загружается по имени в runtime текущей сессии.

Только третье состояние подтверждает runtime-доступность. `hermes skills list` является вспомогательной проверкой и недостаточен при ошибке загрузки по имени.

## Последствия для v0.3

- Установочный шаблон сохраняет локальные навыки и не переносит их в глобальный каталог Hermes.
- Человек выполняет `hermes skills trust` после установки и принимает изменение доверенного runtime-состояния Hermes.
- Стабильный release, tag, публикация и human acceptance этим решением не утверждаются.
- U-003 остаётся открытым и не закрывается этим решением.

## Перенос в v0.4

В v0.4 после отдельного решения человека можно исследовать исправление абсолютного `TERMINAL_CWD`, повторную runtime-валидацию в Hermes Desktop и гипотезу о глобальных навыках Hermes. Глобальные навыки не являются частью v0.3 и не должны заменять локальную проектную изоляцию без отдельной проверки.
