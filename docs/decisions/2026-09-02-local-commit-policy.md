# Политика локальных коммитов ИскИн

**Дата:** 2026-09-02
**Статус:** утверждено человеком
**Область:** только разработка репозитория ИскИн

## Решение

1. Hermes самостоятельно создаёт локальный коммит после завершения логически цельного изменения.
2. Коммит разрешён только после прохождения обязательных проверок из `docs/development/verification-policy.md`, определённых составом подготовленных файлов.
3. В коммит не включаются посторонние изменения, временные файлы, кэши, секреты, приватные данные, случайные сгенерированные артефакты и незавершённая работа.
4. При неясной границе, неизвестных изменениях, либо при `FAIL` или невозможности обязательной проверки Hermes не создаёт коммит и сообщает человеку о препятствии.
5. `NOT_APPLICABLE` допустим только с конкретным объяснением, почему проверка не относится к изменению.
6. Локальный коммит не означает human acceptance, стабильный релиз или публикацию.
7. Явный запрет на коммит в конкретной задаче имеет приоритет над этой политикой.
8. Создание или изменение remote, `push`, тег, GitHub Release и переписывание Git-истории требуют отдельного разрешения человека.
9. Итоговый отчёт содержит hash коммита, его содержание, выполненные проверки и оставшиеся вопросы.

## Граница решения

Эта политика применяется только к разработке самого репозитория ИскИн. Она не является частью устанавливаемого ядра и не изменяет `package/template/AGENTS.md`, `package/template/process/**` или другие файлы устанавливаемого шаблона.

Универсальная политика локальных коммитов для проектов, использующих ИскИн, отложена до начала работы над v0.4.

## Последствия

Каноническая матрица проверок находится в `docs/development/verification-policy.md`. Корневой `AGENTS.md` содержит только обязательный указатель на неё. Политика не разрешает внешний GitHub-эффект: remote, push, тег и release остаются отдельными human-gated действиями.
