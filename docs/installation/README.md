# Установочный контракт ИскИн v0.3

**Статус:** границы утверждены человеком `2026-09-02`; код установщика не реализован.

## Назначение

Установщик локально размещает официальный пакет ИскИн v0.3 в новой или пустой папке продукта и оставляет проверяемый след установки. Он не разворачивает продуктовый код и не настраивает глобальную среду Hermes.

## Допустимая целевая папка

Установка разрешена только если целевой путь:

1. не существует; либо
2. существует и пуст; либо
3. содержит только `.git` и его служебные каталоги.

Любой другой файл или каталог означает отказ до изменения целевой папки. Установка в существующий непустой продукт в v0.3 не поддерживается.

## Источник и целостность пакета

Основной источник — официальный архив GitHub Release. Вызов скачивания выполняется вызывающей стороной; после получения архива все проверки и установка происходят локально. До распаковки установщик должен:

- получить версию из метаданных пакета;
- проверить ожидаемый SHA-256 архива;
- проверить, что архив содержит только разрешённую структуру;
- отказаться от запуска при несовпадении версии, SHA-256 или структуры.

Ожидаемые параметры передаются явно: `release_version`, `archive_path`, `expected_sha256`, `target_path`. Отсутствующий digest или версия — ошибка предварительной проверки, а не повод принять значение из архива как ожидаемое.

Поддержка произвольных URL, автоматического подключения GitHub и скачивания зависимостей не входит в v0.3.

Формат release утверждён отдельным решением `docs/decisions/2026-09-02-v0.3-release-format.md`:

```text
iskin-v0.3.0.zip
install-iskin.py
SHA256SUMS
```

Внутри архива ожидается корень `iskin-v0.3.0/` с `VERSION`, `package-manifest.json` и `template/`. Точная schema v1 manifest зафиксирована в `docs/decisions/2026-09-02-v0.3-package-manifest-v1.md`: верхний уровень содержит только `schema_version`, `release_version`, `root`, `template_root` и `files`; каждая запись `files` содержит только `path` и строчный `sha256`; список отсортирован и является полным allowlist файлов шаблона. Пути в `files` относительны `template_root`; `VERSION`, manifest и каталоги в список не входят. Архив не содержит установщик и `SHA256SUMS`.

## Поведение установки

Установщик:

- создаёт целевую папку только после успешных предварительных проверок;
- никогда не перезаписывает существующий файл;
- размещает содержимое пакета атомарно через временный staging-каталог;
- создаёт `.iskin/version` с версией установленного пакета;
- создаёт `.iskin/installation-manifest.json` с версией, SHA-256 пакета, списком относительных файлов и временем установки;
- при явном локальном выборе выполняет `git init`, если папка ещё не является Git-репозиторием;
- не создаёт commit, remote или push;
- не устанавливает зависимости и не меняет глобальные настройки;
- не подключает GitHub автоматически;
- не удаляет и не обновляет ранее установленное содержимое.

Если какая-либо операция после начала staging завершается ошибкой, staging удаляется, а целевая папка возвращается к состоянию до установки. Для существующей пустой папки это означает отсутствие новых файлов после ошибки. До последнего read-back установщик не должен объявлять установку успешной.

## Проверка после установки

После размещения выполняется локальная проверка:

- `.iskin/version` существует и соответствует ожидаемой версии;
- `.iskin/installation-manifest.json` существует и содержит проверенный SHA-256;
- каждый обязательный файл структуры присутствует;
- каждый установленный файл входит в manifest и не имеет неожиданных путей;
- `AGENTS.md` и шесть проектных навыков имеют корректную структуру;
- product memory и telemetry остаются пустыми шаблонами;
- в пакете отсутствуют Budget- и toolchain-specific материалы;
- установщик не создавал commit, remote или внешнюю публикацию.

Результат — локальный отчёт с версиями, количеством файлов, SHA-256, проверками, исходным состоянием целевой папки и причиной отказа при ошибке. Отчёт не отправляется во внешнюю систему автоматически.

## Разрешённый состав v0.3

Пакет должен соответствовать `package/template/`. Продуктовые runners, evidence, статусы, fixtures и toolchain-настройки добавляются уже после установки владельцем конкретного продукта.

## Не входит в v0.3

- установка в непустой проект;
- автоматическое обновление или удаление;
- графический интерфейс;
- автоматическое подключение GitHub;
- исправление runtime-индексации проектных навыков U-003;
- улучшения v0.4 и второй полигон;
- commit, remote, release и push.

## Критерий готовности будущего установщика

Реализация может считаться соответствующей этому контракту только после read-back целевой папки, проверки manifest и SHA-256, негативных проверок для непустой папки и проверки failure atomicity. Минимальный набор сценариев: новая папка, пустая папка, папка только с `.git`, папка с одним посторонним файлом, несовпадение версии, несовпадение digest, неожиданный путь в архиве, отказ во время staging и повторный запуск.

В этом изменении реализация и запуск установщика не выполняются.
