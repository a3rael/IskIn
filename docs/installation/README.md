# Установочный контракт ИскИн v0.3 и режимы v0.4

**Статус:** границы утверждены человеком `2026-09-02`; локальный установщик и read-only валидатор реализованы.

Для ветки v0.4 installer сохраняет один и тот же проверенный manifest/allowlist контракт и выбирает финальное сообщение по фактическому составу package. Подробное human decision: `docs/decisions/2026-09-06-v0.4-installer-runtime-mode.md`.

## Назначение

Установщик локально размещает официальный пакет ИскИн v0.3 в новой или пустой папке продукта и оставляет проверяемый след установки. Он не разворачивает продуктовый код и не настраивает глобальную среду Hermes. Граница надёжности зафиксирована в `docs/decisions/2026-09-02-v0.3-safe-installation.md`.

## Допустимая целевая папка

Установка разрешена только если целевой путь:

1. не существует; либо
2. существует и пуст; либо
3. содержит единственный элемент `.git`, представленный обычной директорией или служебным Git worktree-файлом.

Любой другой файл или каталог означает отказ до изменения целевой папки. Установка в существующий непустой продукт в v0.3 не поддерживается.

## Источник и целостность пакета

Основной источник — официальный архив GitHub Release. Вызов скачивания выполняется вызывающей стороной; после получения архива все проверки и установка происходят локально. До распаковки установщик должен:

- получить версию из метаданных пакета;
- проверить ожидаемый SHA-256 архива;
- проверить, что архив содержит только разрешённую структуру;
- отказаться от запуска при несовпадении версии, SHA-256 или структуры.

Ожидаемые параметры передаются явно: `release_version`, `archive_path`, `expected_sha256`, `target_path`. Отсутствующий digest или версия — ошибка предварительной проверки, а не повод принять значение из архива как ожидаемое.

Поддержка произвольных URL, автоматического подключения GitHub и скачивания зависимостей не входит в v0.3.

Формат release утверждён отдельным решением `docs/decisions/2026-09-02-v0.3-release-format.md`:

```text
iskin-v0.3.0.zip
install-iskin.py
SHA256SUMS
```

Внутри архива ожидается корень `iskin-v0.3.0/` с `VERSION`, `package-manifest.json` и `template/`. Точная schema v1 manifest зафиксирована в `docs/decisions/2026-09-02-v0.3-package-manifest-v1.md`: верхний уровень содержит только `schema_version`, `release_version`, `root`, `template_root` и `files`; каждая запись `files` содержит только `path` и строчный `sha256`; список отсортирован и является полным allowlist файлов шаблона. Пути в `files` относительны `template_root`; `VERSION`, manifest и каталоги в список не входят. Архив не содержит установщик и `SHA256SUMS`.

## Локальная воспроизводимая сборка

Для development-сборки комплекта используется:

```text
python3 installer/build_release.py \\
  --release-version 0.3.0 \\
  --output-dir /path/to/output
```

`output-dir` может быть новой или пустой папкой. Generator сначала создаёт staging на той же файловой системе, формирует manifest и ZIP с фиксированным порядком, timestamp `1980-01-01 00:00:00`, `ZIP_STORED`, пустыми extra fields/comment и фиксированными обычными file attributes. Затем он запускает read-only validator, пробную установку только во временный проект, сравнение байтов с `package/template/` и read-back installation metadata. Только после этого публикуются ровно три файла без перезаписи.

Одинаковые исходники и версия должны давать побайтово одинаковые `iskin-v<version>.zip`, `install-iskin.py` и `SHA256SUMS`. Локальная сборка не означает стабильный release, human acceptance или production readiness. Generator не выполняет network/push/tag/GitHub Release; публикация остаётся отдельным человеческим решением. Контракт подробно зафиксирован в `docs/decisions/2026-09-02-v0.3-reproducible-release-build.md`.

## Поведение установки

Установщик:

- полностью проверяет release-пакет до записи в целевой проект;
- для новой папки использует staging на той же файловой системе и атомарное переименование;
- для существующей пустой или `.git`-only папки переносит только новые файлы;
- никогда не перезаписывает существующий файл и сохраняет существующий `.git` без изменений;
- создаёт `.iskin/version` с версией установленного пакета;
- создаёт `.iskin/installation-manifest.json` последним среди установочных metadata-файлов;
- выполняет `git init` только при явном флаге `--init-git`;
- не создаёт commit, remote, branch ref, tag или push;
- не устанавливает зависимости, не меняет глобальные настройки и не подключает GitHub автоматически;
- при обычной обнаруженной ошибке удаляет только созданные им файлы и каталоги.

Если операция после начала записи завершается обычной обнаруженной ошибкой, установщик пытается удалить только созданные им пути. При успешном rollback существующая целевая папка возвращается к исходному состоянию; если очистка не завершилась, результат явно сообщает об ошибке rollback и оставшихся путях. Внезапное выключение, `SIGKILL` и аварийное завершение ОС во время записи являются известным ограничением v0.3; crash-safe recovery и журнал незавершённой установки отложены.

## Проверка после установки

После размещения выполняется локальная проверка:

- `.iskin/version` существует и соответствует ожидаемой версии;
- `.iskin/installation-manifest.json` существует и содержит проверенный SHA-256;
- каждый обязательный файл структуры присутствует;
- каждый установленный файл входит в manifest и не имеет неожиданных путей;
- `AGENTS.md` и project-local skills, если они есть в manifest, имеют корректную структуру;
- product memory и telemetry остаются пустыми шаблонами;
- в пакете отсутствуют Budget- и toolchain-specific материалы;
- установщик не создавал commit, remote или внешнюю публикацию.

Результат — локальный отчёт с версиями, количеством файлов, SHA-256, проверками, исходным состоянием целевой папки и причиной отказа при ошибке. После успешной установки CLI печатает режим, определённый по manifest: ручной `hermes skills trust` только для package с project-local skills либо global-runtime handoff без trust для package без них. Установщик не выполняет ни один из этих последующих шагов. Отчёт не отправляется во внешнюю систему автоматически.

## Разрешённый состав v0.3

Пакет должен соответствовать `package/template/`. Product-specific runners, evidence, статусы и fixtures добавляются уже после установки владельцем конкретного продукта. Product-specific fixtures в пустом шаблоне отсутствуют; process-only fixture `process/fixtures/provenance-drift/` присутствует для проверки provenance drift, не является product evidence и не запускает продуктовый код.

## Подключение project-local skills после установки

Если manifest содержит файлы под `.hermes/skills/` или `.agents/skills/`, установщик не изменяет доверенное runtime-состояние Hermes автоматически. В корне установленного проекта выполни вручную:

```text
cd <project-root>
hermes skills trust
```

Затем:

1. полностью перезапусти Hermes Desktop;
2. открой установленную папку как Hermes Desktop Project;
3. создай новую сессию;
4. проверь через runtime все шесть навыков: `understand-state`, `choose-next-action`, `change-product`, `prove-result`, `challenge-result`, `control-pilot`;
5. отдельно различай наличие файла, отображение навыка как `local/enabled` и фактическую успешную загрузку навыка по имени в текущей сессии.

`hermes skills list` недостаточен: если загрузка по имени завершается `Skill not found`, runtime-доступность не подтверждена. Если текущая сессия передаёт относительный `TERMINAL_CWD=./workspace`, а навыки не загружаются, это известный случай несовместимости Hermes Desktop v0.3, а не успешное подключение; само относительное значение не доказывает причину. Подробный сценарий, актуальное уточнение и граница доказательства описаны в `docs/integration/hermes-desktop.md`, `docs/decisions/2026-09-05-v0.3-runtime-observations-clarification.md` и решении `docs/decisions/2026-09-03-v0.3-project-skill-runtime-boundary.md`.

## Global runtime v0.4

Если manifest не содержит файлов под `.hermes/skills/` или `.agents/skills/`, project trust не требуется и `hermes skills trust` не является шагом установки. Такой проект использует заранее установленный global runtime ИскИн. Installer не устанавливает, не обновляет и не удаляет global skills и не меняет Hermes configuration, profile, trust или gateway. Фактическую доступность global skills необходимо проверить в новой сессии Hermes; CLI registry или наличие установленных bytes сами по себе runtime-load не доказывают.

## Не входит в v0.3

- установка в непустой проект;
- автоматическое обновление или удаление;
- графический интерфейс;
- автоматическое подключение GitHub;
- исправление runtime-индексации проектных навыков U-003;
- улучшения v0.4 и второй полигон;
- commit, remote, внешний release и push.

## Проверенный критерий установщика v0.3

Соответствие установщика проверяется read-back целевой папки, installation manifest и SHA-256, негативными проверками для непустой папки, симлинков, повторного запуска и проверкой rollback после обычной ошибки. Минимальный набор сценариев реализован в `installer/test_install_iskin.py`.
