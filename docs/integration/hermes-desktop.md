# Интеграция ИскИн v0.3 с Hermes Desktop

## Назначение

Этот документ описывает подключение шести локальных проектных навыков ИскИн и доказательство их runtime-доступности. Он не заполняет product memory, не создаёт product evidence и не утверждает стабильный release.

Каноническое решение о границе совместимости: `docs/decisions/2026-09-03-v0.3-project-skill-runtime-boundary.md`.

## После установки

Выполни в корне установленного проекта:

```text
cd <project-root>
hermes skills trust
```

`hermes skills trust` — обязательный ручной шаг. Он изменяет доверенное runtime-состояние Hermes. Установщик эту команду не выполняет.

Затем:

1. полностью перезапусти Hermes Desktop;
2. открой установленную папку как Hermes Desktop Project;
3. создай новую сессию;
4. проверяй навыки в этой новой сессии, а не только по файлам на диске.

## Что именно проверять

Проверь через runtime загрузку по имени всех шести навыков:

- `understand-state`;
- `choose-next-action`;
- `change-product`;
- `prove-result`;
- `challenge-result`;
- `control-pilot`.

Для каждого имени зафиксируй отдельно:

| Состояние | Что оно доказывает |
|---|---|
| `SKILL.md` присутствует в `.hermes/skills/<skill-name>/` | файл установлен на диске |
| навык указан как `local/enabled` | runtime-каталог видит навык |
| успешная загрузка навыка по имени в текущей сессии | runtime фактически доступен |

Только третье состояние является доказательством runtime-доступности. `hermes skills list` недостаточен, если загрузка навыка по имени завершается `Skill not found`.

## Известное ограничение v0.3

В текущем Hermes Desktop runtime получает `TERMINAL_CWD=./workspace`, хотя фактический `PWD` является абсолютным путём проекта. Поэтому локальные навыки могут не разрешаться даже после успешного `hermes skills trust`.

Если одновременно выполняются условия:

- проектные `SKILL.md` присутствуют;
- trust выполнен;
- `hermes skills list` показывает навык;
- загрузка по имени завершается `Skill not found`;
- runtime использует относительный `TERMINAL_CWD=./workspace`,

результат классифицируется как известное ограничение Hermes Desktop v0.3 и отсутствие подтверждённой runtime-доступности. Это не считается успешным подключением.

Отдельный runtime-процесс с корректным абсолютным `TERMINAL_CWD` успешно загружает все шесть навыков версии `0.3.0`, но такой контрольный результат не переносится автоматически на уже открытую Desktop-сессию.

## Не делать в v0.3

- не считать наличие файла доказательством загрузки;
- не считать один `hermes skills list` доказательством загрузки;
- не добавлять файловый fallback вместо runtime-навыков;
- не переносить навыки в глобальный каталог Hermes;
- не записывать это ограничение в `product-memory/uncertainties.md` установленного проекта;
- не заполнять `intent`, `outcomes`, `evidence` или другие продуктовые документы во время этой проверки.

U-003 остаётся открытым и переносится в v0.4. Возможный переход к глобальным навыкам — только гипотеза для отдельного решения и проверки v0.4.
